> v1 覆盖里程碑 **M1–M3 + 部分 M4**：核心链路全部跑通，7 屏界面（含 FR-16 时段新闻研判）。

**2026-11-28 第十二轮（多平台中心）**

- **新增「多平台中心」**：左侧导航放在「每日新闻」下面，主模块下挂 B站、贴吧、微博、知乎、抖音五个子模块；顶部页面与左侧子项都能打开。
- **官方页面直接在本程序打开**：每个子模块用本程序自己的 WebView2 窗口加载平台官网（不跳系统浏览器、不嵌 iframe、不注入脚本、不抓页面），登录/扫码/短信验证码/浏览都由官方页面完成，降低平台风控触发概率。
- **登录态保留**：每个平台使用独立的持久化浏览器目录（`data\multisite\<平台>`），关闭窗口后 Cookie 仍保留；多平台中心的登录态与设置页的应用内登录面板互相独立。同一平台已经打开时提示切换已有窗口，不重复创建。
- **安全边界**：只允许五个硬编码官方 URL，前端不能传任意网址；接口仅本机回环地址可调，退出程序时一并销毁多平台窗口。
- **接口**：`GET /api/multisite/sites`、`POST /api/multisite/open {site}`；`site` 取值 `bilibili|tieba|weibo|zhihu|douyin`。

**2026-11-28 第十一轮（平台登录 / 退出 / 热搜正文）**

- **五个平台登录**：设置页「平台登录」卡片打开**程序自己的登录面板**，不再直接弹出微博 / 百度 / 抖音 / B站 / 知乎的网页登录页。面板按应用风格做了平台页签、登录方式（账号密码 / 手机验证码 / 扫码）和状态提示；账号密码只用于本次登录，后台在隐藏 WebView2 里填入平台表单，**不保存账号密码，也不把 Cookie 明文写进状态文件**。平台若要求图形验证码、风控确认或页面改版，会直接提示“登录未完成”，不会假装成功。
- **短信验证码通道**：微博、抖音、知乎支持在应用内填手机号、点“发送验证码”，短信到达后在同一个面板填验证码并提交；验证码只在后台任务内存里停留，不写配置文件。
- **扫码通道**：微博、百度、B站、抖音支持把平台二维码取到应用面板里显示，用对应 App 扫码后后台自动检测登录；抖音默认打开扫码方式并自动生成二维码。知乎二维码是跨域 canvas，当前无法安全取出，面板会提供“改用官方页面登录”按钮回退到平台官方扫码页。二维码过期或平台拒绝时，可以点“生成 / 刷新二维码”重试。
- **官方页面兜底**：如果应用内账号密码 / 短信 / 扫码都被平台风控拦住，面板底部「改用官方页面登录」会打开该平台官方登录页（用户可见的兜底，不是默认路径）。
- **登录后读热搜正文**：热搜条目点标题时，后端先用同一个 WebView2 用户目录加载页面（页面里已带登录 Cookie），再按平台选择器抽取正文：微博取热门微博正文，知乎取问答正文，B站取视频标题/简介，抖音取视频文案/简介，百度取搜索结果摘要。正文落到 `article_cache` 与当天 `YYYY-MM-DD.正文.html`，仍可「打开本地正文文件」。
- **需要登录会明确提示**：未登录点平台热搜时，正文弹窗显示“需要先登录X，登录后再点一次标题即可读取”，并提供「登录X后查看」按钮；应用内登录面板登录成功后，再点一次标题即可重新抓取。旧版本把这类链接标成“抓不到正文”的缓存会自动重试，不再卡住。
- **退出账号是真退出**：设置页每个已登录平台都有「退出账号」，打开该平台官方退出页；微博/百度/B站会直接清登录 Cookie，抖音/知乎需在页面右上角头像菜单点退出，检测到登录 Cookie 消失后自动关闭窗口并把本机状态改为未登录。另有「清除记录」只清本机状态，不修改平台账号。
- **退出程序收尾**：主程序退出时会销毁所有还开着的平台登录/退出窗口，避免残留 WebView2 子窗口。

**2026-11-27 第七轮（修「打包后窗口一闪就退」）**

- **现象**：打完包双击 `dist\日常小助手.exe`，后台起来了（日志有「日常小助手 已启动」），但窗口瞬间消失，服务跟着停；偶尔会残留一个标题为 `127.0.0.1` 的 Edge 窗口。
- **根因**：`dist\日常小助手.exe` 被 **Win7 版（Python 3.8 构建）** 覆盖了。3.8 的包不含 pywebview → 走 Edge `--app` 回退；而专属 `browser-profile` 已被上一次残留的 Edge 进程占着，Chromium 单实例把新窗口交给老进程后自己退出，程序误判「窗口已关闭」→ 关停后台服务。正常主版日志里必须有 `已打开 WebView2 无边框窗口：…`，被覆盖的包里没有这行。
- **修复**：重新用 Python 3.13 打主版（13.65MB），Win7 版单独落在 `dist\win7\日常小助手.exe`（9.94MB）。新增 `desktop\打包exe-主版.bat`：打完会检查 exe 体积，小于 12MB 直接报错（说明 pywebview 没打进去 / 被 3.8 包覆盖）。
- **打包顺序（重要）**：先跑 `打包exe-Win7.bat`，最后再跑 `打包exe-主版.bat`。主版必须是最后一步，否则会被小包覆盖。
- 遇到残留 Edge 窗口：关掉那个 `127.0.0.1` 窗口，或删 `data\browser-profile` 后重启（只影响窗口，不删数据）。

## 1. 快速开始

### 方式一：直接运行打包产物（推荐，无需 Python）

| 产物 | 用法 |
|---|---|
| `dist\日常小助手.exe` | 双击即可，**不需要安装 Python、不需要 pip install**。自动打开无边框应用窗口，地址 `http://127.0.0.1:8765/`。适用 Windows 10 / 11 |
| `dist\win7\日常小助手.exe` | **Win7 兼容版**（Python 3.8.10 运行时，功能与主版相同），适用 Windows 7 SP1 64 位。把整个 `win7` 文件夹拷到目标电脑再用，前置条件见下方「Win7 兼容版」 |

exe 首次运行会在 **exe 同目录**创建 `data\`（配置、SQLite、密钥、日志、WebView2 用户数据目录），卸载/备份时保留这个目录即可。
退出方式：点顶栏 **「退出」按钮**（会同时关闭窗口与后台服务），或命令行 `日常小助手.exe --stop`；Alt+F4 或系统关闭按钮只会收进托盘，再双击 exe 会直接唤回已运行的窗口。

**桌面端窗口说明**：用 **pywebview + 系统 WebView2** 承载界面，是无原生标题栏、无系统边框的干净窗口。
- **拖动**：按住顶栏空白处（品牌区或中间空白）拖动，窗口 1:1 跟手，不闪不抖。
- **全屏**：点右上角「□」铺满工作区（任务栏保留），再点一次还原到原尺寸；双击顶栏同样可以。
- **缩小**：点「─」最小化到任务栏；窗口右下角可拉边框调整大小。
- 前提是系统装有 **WebView2 运行时**（Win10/11 自带 Edge 的机器一般都有）。若没有，程序自动回退到 Edge `--app` 窗口（旧的拖动方案）。
若用普通浏览器打开 `http://127.0.0.1:8765/`，自绘窗口控件会自动隐藏，不影响使用。

**依赖：Python 3.10+**、Windows 有 WebView2 运行时；窗口宿主需要 `pip install pywebview`（未安装时回退到 Edge `--app`）。

```bat
cd /d D:\WorkSpace\黄金积存提醒\v2

python -X utf8 desktop\run.py
```

界面地址 `http://127.0.0.1:8765/`（后台服务只监听本机回环地址）。

配置、数据库、密钥、调度器都只保存在本机 `desktop\data\`，不存在第二个程序，也没有任何跨端同步。

### 邮箱（FR-14）
点「设置 → 邮箱配置（SMTP）」，填：

- 单日上限、超时、重试次数

授权码只存本端安全存储：Windows 用系统 DPAPI，`config.json` 里只有 `secure-store://` 引用，界面默认掩码，日志/邮件/导出均脱敏。

### DeepSeek（FR-15）
- API Key、Base URL（默认 `https://api.deepseek.com`）、快报/日报模型、`max_tokens`、超时、重试、每日调用上限、token 预算、JSON Output 开关
- 「测试连接」会产生一次极小额调用；错误 Key 会明确报错且**不清空已保存的 Key**
- 用量按实例独立计数，手动获取计入同一预算，超限自动降级为「仅数据不研判」

> 未配置 Key 时程序照常运行：价格与新闻照常采集、邮件照常可发（含 AI 不可用标注），研判卡显示「信号不明确」。

### 时段新闻研判（FR-16）
侧栏 / 底部 Tab「时段新闻研判」→ 选预设（近 3 个月 / **近半年（默认）** / 近一年）或「自定义日期」填起止日期
→ 选未来观察尺度（2–4 周 / 1–3 个月 / 3–6 个月）→ 点「开始采集并 AI 研判」。
需要发信时勾选「同时发送到邮箱」（**默认不勾选**）；结果页可看数据源状态、主题与月度分布、AI 倾向、反向情形、关注点、新闻样本，并可预览报告与回看最近运行记录。

- 设置页「时段新闻研判配置」可调：默认区间、观察尺度、最大样本数、AI 最大输入条数、最小样本数、单源超时、采集总时限、重复运行间隔、默认发信、各档案源开关；Alpha Vantage 历史新闻源需要单独填 Key（免费申请约 20 秒，25 次/天；Key 只存本端安全存储、界面掩码，保存后该源自动打开）。
- 采集有总时限（默认 22 秒、单源 10 秒），GDELT / Google News 等源不可达或返回 429 会**如实标出**，不会静默补数。

- 无 DeepSeek Key、样本少于阈值或输出出现禁词时，一律降级为「信号不明确 / 低置信度」；**只做条件化情景归纳，不是价格预测**，报告固定附带免责声明与数据缺口说明。

### 推送时点
默认 08:00 每日总结 / 12:30 快报 / 20:00 快报，可任意增删改、改类型、启停、清空；静默时段默认 23:00–07:00（支持跨日）。

> ✅ **单端发送**：本版只有桌面端一个程序，定时推送只由本端发出，不存在两处重复发信的问题。设置页第一张卡片「本端定时推送总开关」可一键关闭自动发信。

### 开机自启动

设置页「开机自启动」卡片，开关即开即关，无需保存。开启后登录 Windows 自动启动本程序（打包版登记 `日常小助手.exe` 路径；源码运行登记 `pythonw.exe + desktop\run.py`）。只影响当前 Windows 用户，不弹 UAC。

### 每日内容（新闻 · 资讯 · 军事，合并设置）

第八轮起，原来的「每日新闻 / 每日资讯 / 每日军事新闻」三张设置卡合并为一张「每日内容」卡：**一套生成时间、一套汇总周期与汇总时间**，三个页签和本地文档照旧保留。

| 项目 | 说明 |
|---|---|
| 每日生成 | 默认 **20:30**，到点后依次生成三份文档（新闻 → 资讯 → 军事），当天任意时刻补做、同一天只做一次 |
| 三份文档 | `data\每日新闻\YYYY-MM\YYYY-MM-DD.md`、`data\每日资讯\...`、`data\每日军事新闻\...`；各自的 `YYYY-MM-DD.正文.html` 全文照旧保存 |

| 周期汇总 | 默认 **21:30**，周期可多选（每天 / 每周 / 每月 / 每半年 / 每年 / 自定义 N 天）；三个模块各出一份汇总文档，再合成**一封**「每日综合汇总」邮件，存 `data\每日综合汇总\<起>至<止>\<周期>.md` |
| 各模块采集范围 | 央视栏目与每栏条数、热搜平台与每平台条数、资讯条数上限（默认 40）、军事条数上限（默认 60），只影响三份文档与页签，不影响上面的时间与邮件 |

- 升级时自动迁移：`daily_all` 继承原「每日新闻」的生成时间与汇总设置；三个旧模块只要有一个开过发信，合并邮件就保持开启，同时把旧模块的发信开关全部关掉，避免继续一天发多封。若原配置勾了「每天」汇总，合并后默认去掉（日报本身每天一封，再发每日汇总会重复），需要可再勾回。
- 设置页按钮：「保存每日内容设置」保存上面的统一项与采集范围；「立即生成三份并合并发信」按当前「发送合并邮件」开关执行；三个「打开…」分别打开新闻 / 资讯 / 军事文档目录。
- 邮件主题前缀跟随发件人显示名：`【今日要闻】每日综合 · 2026-11-27（周五）`，汇总为 `【今日要闻】每日综合汇总 · 周报（AI 汇总）`。
- 三个页签的「立即生成」仍只生成单份、不发信；要发合并邮件请用「每日内容」卡的按钮，或等定时任务。
- AI 只做事实归纳与条件化提示，不给点位与仓位；AI 不可用时，合并邮件降级为三个板块的摘录，不会空白。

## 7. 数据源、口径与合规

**已实测可用（2026-11-26）**：`api.gold-api.com/price/XAU`、`hq.sinajs.cn/list=hf_XAU`、
`open.er-api.com/v6/latest/USD`、CNBC/WSJ/新浪财经**滚动**接口。

**接入生产前请逐家重新核验可用性、调用条款、频率限制与再分发许可**；需求文档中的选型只是候选，不是已验证结论。

**军事新闻源（2026-11-27 实测）**：国内 `www.81.cn/yw_208727/index.html`（中国军网要闻，列表页标题后粘「，26-11-27 06:30」需裁切）、`military.people.com.cn`（人民网军事）、`military.cctv.com/data/index.json`（央视军事滚动 JSON，需浏览器 UA + Referer）；国际用 RSS：Defense News / Defense One / Military Times / Air Force Times / Army Times / Navy Times / Marine Corps Times / Naval News / The War Zone / DefenseScoop / Air & Space Forces / Task & Purpose（垂直站直接要闻）+ Global Times 英文版 / France 24 / UN News（按英文军事关键词筛标题）。Reuters（超时）、AP（403）、BBC / Al Jazeera / Guardian / NYT 等在本机网络不可达，预置但默认关闭。央视 CMS 军事栏目接口、新华网军事、环球网军事、中国网军事、央广军事均因无数据 / 壳页 / 停更放弃，可回看本轮记录。

**口径硬规则（代码已实现）**：
- 银行积存金买卖价才是真实成交价 → **未接入，绝不冒充**
- 上金所 Au99.99 是**国内实时金价参考口径**（交易所现货，**非银行成交价**）→ 已接入新浪行情，总览「国内实时金价」即此项
- XAU/USD 是驱动口径；折算价 = XAU/USD ÷ 31.1034768 × USD/CNY，**单独标注「非银行成交价」**
- 每个价格带口径角色、来源、**源报价时间**、抓取时间、质量标记；禁止用抓取时刻顶替源报价时间
- 多源分歧 >1% 时并列展示，不静默挑一个；涨=红、跌=绿；所有时间按北京时间

**已知限制（v2 · 桌面单端）**：
1. 银行报价需自备官方接口（Q1/Q9 未确认）；适配器已预留 `generic_json`。Au99.99 已接入（新浪行情），但它是交易所现货参考价，不是银行积存金成交价。
2. 「重启补发当日总结」已升级为启动后补生成最近 N 天（默认 2 天）：只用本机已存条目，不重新采集、不发旧邮件；若当天条目已被清理则无法凭空补出。时点后的短窗口补发（默认 10 分钟）仍然保留。
3. 新闻摘要来自 RSS 自带描述，未调用模型做中文摘要（避免额外成本与幻觉风险）。
4. exe 的无边框窗口依赖系统 **WebView2 运行时**（Win10/11 一般自带）；没有时自动回退到 Edge `--app` 窗口，此时窗口由浏览器自己管理（会有原生标题栏与 X），且无自绘窗口控制。
7. 「金价详细走势」的国际金价没有稳定的免费分时源，「今日」一档展示近 7 日日 K 并如实标注；国内日 K 用沪金主力合约代表，与 Au99.99 现货相差数元。
8. AI 的走向预判与投资建议是基于公开新闻与区间涨跌的**条件化参考**，置信度低或新闻缺失时方向强制「信号不明确」，短期建议自动降为保守表述；不构成交易指令。
5. FR-16 的公开档案源（GDELT / Google News）在部分网络返回 429 或超时，因此不填 Alpha Vantage Key 时，「近半年 / 近一年」的完整覆盖度不保证；程序会展示每个源的状态与样本数，覆盖不足时不给出方向性结论。RSS 与新浪滚动只能覆盖区间尾部（新浪滚动约 8 天、约 200 条），本端库只覆盖安装后已采集的新闻。
